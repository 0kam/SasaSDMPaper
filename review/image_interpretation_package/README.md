# ササ減少セルの目視判読パッケージ

2012→2021 の植生分類図（1 m グリッド）で検出された**ササ→非ササの減少 2,468 セル**が、
真のササ衰退なのか、木本の樹冠がササを覆い隠したのか、あるいは分類器の不安定さ
（境界画素の入れ替わり）なのかを、タイムラプス写真の対画像で判読するための一式です。

判読者は著者本人です。所要時間の目安は 129 サンプルで 2〜4 時間。

---

## 1. まず何をするか（3 分で始める）

1. **対照サンプルで「見え方」を覚える。**
   - `contact_control_stable_sasa.png` … 両年ともササ（1→1）。淡い黄緑、なめらかで一様な草原状。
   - `contact_control_stable_dwarfpine.png` … 両年ともハイマツ（7→7）。暗い青緑、ごつごつした
     クッション状の塊。急な岩礫斜面に多い。
   この 2 枚を並べて眺めれば、以降の判読の基準ができます。**ここを飛ばさないでください。**
2. **`overview_sasa_change.png`** で、変化がどこに分布しているか（室堂遊歩道沿いの中腹の帯）と、
   129 サンプルがどこから引かれたかを把握する。
3. **`interpretation_tool.html`** をブラウザで開き、`B001` から順に画像を見て判定を入力していく
   （§3 の判定基準、§3.5 の操作方法）。CSV を直接手入力したい場合は
   `interpretation_sheet.csv` の `verdict` 列を埋めても構いません。

## 3. 判読手順

### 3.1 見る順番

`interpretation_sheet.csv` の各行について、

1. 画像を **等倍（100 %）以上** に拡大して開く（ツールなら <kbd>+</kbd> / ホイール、
   `blind_overlay/<blind_id>.png` を直接開くなら Preview.app で ⌘0）。
2. 判定対象は、**マゼンタの照準（十字）が指している枠の内側**の 1 m セルです。
   枠は 4 パネルすべてに同じ位置で描いてあります。詳しくは下の「対象セルの枠と照準」。
3. 左（2012）と右（2021）を往復して比べる。上段（緑葉期）と下段（紅葉期）は**両方**見ること。
   紅葉期はハイマツ（常緑・暗緑のまま）と落葉低木（赤〜橙）とササ（黄褐色）の分離に効きます。
4. `verdict`、`confidence`、`notes` を記入する。

判断に迷った場合のみ、その行の判読を確定させたあとで `sample_key.csv` から `sample_id` を引き、
`crops/<sample_id>.png` の注釈付き図（ラベル重ね）を見て構いません。ただしその場合は
`notes` に `unblinded` と書き残してください。

#### 対象セルの枠と照準

「どのピクセルが判定対象か分からない」という指摘を受けて、`blind_overlay/` を追加しました。
`blind/` とまったく同じ切り出しに、次の 2 つだけを重ねたものです。

- **マゼンタの細線（1 px）** … 判定対象の 1 m セルを、`sample_loss_crops.py` と同じカメラモデルで
  画像座標に投影したフットプリント（輪郭のみ、塗りなし）。
- **マゼンタの照準（十字、黒縁つき）** … 枠が小さくて見つけにくいときの目印。
  枠には決してかからない位置に描いてあります。

**全 129 サンプルで色・線幅・形は完全に同一**で、位置以外の情報（クラス・遷移タイプ・ラベル）は
一切含みません。盲検は保たれます。

**<kbd>o</kbd> キー（またはサイドバーの「対象セルの枠を表示」チェックボックス）で枠の表示／非表示を
切り替えられます。既定は表示 ON。**拡大率と表示位置は切り替えても維持されます。

**枠は必ずオフにして中身も確認してください。** 枠は実寸なので、遠景のセルでは
中央値 7.3 × 4.4 px（最小 4.4 × 0.7 px、最大 67.6 × 23.2 px）しかなく、
1 px の輪郭線が対象セルの大半を覆ってしまう場合があります。
枠 ON で位置を確認 → <kbd>o</kbd> で OFF にして中身を見る、という往復が基本の使い方です。

**枠の位置には誤差があります（重要）。** 枠は再フィットしたカメラモデルによる投影で、
GCP 再投影誤差は RMSE 6.3 px / 中央値 2.3 px、さらに 1 m セルの投影位置には 10〜20 px 程度の
非系統誤差が残ります（§5-3）。したがって**枠は 1〜2 セル分ずれうる**と考えてください。
枠の内側だけを見るのではなく、枠を中心に半径 ±20 px 程度の近傍を見て判断し、
「枠の位置は概ねここ」という程度に受け取るのが正しい使い方です。
枠のすぐ外に明らかな樹冠拡大がある場合などは、`notes` にその旨を書き残してください。

### 3.2 判定区分（`verdict` 列）

CSV には**半角英数のキー**を入力してください（集計を機械的に行うため）。

| 入力する値 | 日本語 | 判定の目安 |
|---|---|---|
| `sasa_loss` | **ササ消失** | 2012 にササ（淡黄緑・なめらか）だった面が、2021 には裸地・岩・雪田跡・枯死状に変わり、木本の樹冠に覆われたのではない |
| `canopy_overgrowth` | **樹冠被覆** | 2012 に見えていたササの面を、2021 には木本の樹冠（暗いハイマツのクッション、または落葉低木の塊）が明らかに覆っている。木本パッチが拡大・合体している |
| `boundary_jitter` | **境界の揺れ** | 2012 と 2021 で見た目がほとんど変わらない。または対象セルが元々ササ／木本の境界線上にあり、1〜2 px の位置ずれや色調差で分類が入れ替わったと考えられる |
| `undecidable` | **判別不能** | 解像度不足、影、雲・霧、露出差、位置ずれが大きい等で判断できない |

補足:

- **`canopy_overgrowth` は「ササが下に残っている」ことを意味しません。**
  写真は樹冠の下を見られません。判定できるのは「木本の樹冠が、かつてササだった場所を覆ったか」
  までです。原稿でもそれ以上には踏み込まないでください（§5）。
- 「2012 と 2021 で何も変わっていない」は `sasa_loss` ではなく **`boundary_jitter`** です。
  これが多ければ、減少面積の相当部分は分類器の不安定性ということになります。
- 迷ったら `undecidable` に逃げず、`confidence` を `low` にして区分を選ぶほうが集計に有用です。

### 3.3 `confidence` 列

`high` / `medium` / `low` のいずれか。

### 3.4 記入シートの列

| 列 | 意味 |
|---|---|
| `blind_id` | 盲検 ID |
| `blind_image` | 見るべき画像への相対パス |
| `dist` | カメラからの距離（m） |
| `m_per_px_horiz` | 視線直交方向の地上分解能（m/px）。小さいほど良い |
| `m2_per_px` | 1 画素が覆う地上面積（m²）。斜面の傾きを含む |
| `align_shift_px` | 2012↔2021 の残差位置ずれ（px）。位相相関で実測 |
| `quality_ok` | `m_per_px_horiz < 0.25` かつ `align_shift_px ≤ 2` なら `yes`。129 件中 124 件が `yes` |
| `verdict` / `confidence` / `notes` | **記入欄** |

`quality_ok == no` の 5 件も判読してかまいませんが、集計時は主解析から外し、感度分析として扱ってください。

### 3.5 判読ツール（ブラウザ）— 推奨

`interpretation_sheet.csv` を手入力する代わりに、画像を見ながらクリック／キーボードで
入力できるローカル HTML ツールが使えます。

`interpretation_tool.html` をダブルクリック（または Chrome にドラッグ＆ドロップ）するだけで開きます。
サーバは不要、通信もしません。**必ず `image_interpretation_package/` 内に置いたまま開いてください**
（画像を `blind_overlay/B001.png` / `blind/B001.png` の相対パスで参照しているため）。

**画面構成**

- 左：画像。**ホイールで拡大縮小**（カーソル位置を中心に）、**ドラッグで移動**、
  **ダブルクリックまたは `0` で全体表示に戻る**。右上の `＋ − ⤢` ボタンでも同じ操作ができます。
  等倍を超えると画素を補間せずに表示するので、境界画素の入れ替わりを見分けやすくなります。
- 右：進捗（入力済み件数と `verdict` 別の集計）、判定・確信度・メモの入力欄、移動、書き出し。
  「対象セルの枠を表示」チェックボックスで枠の ON/OFF を切り替えられます（<kbd>o</kbd> キーと同じ）。

**キーボード操作**（画面右下にも一覧が出ています）

| キー | 動作 |
|---|---|
| `1` `2` `3` `4` | `sasa_loss` / `canopy_overgrowth` / `boundary_jitter` / `undecidable`（同じキーをもう一度押すと取り消し） |
| `q` `w` `e` | `confidence` = `high` / `medium` / `low` |
| `→` `Space` `j` | 次のサンプル |
| `←` `k` | 前のサンプル |
| `u` | 次の未入力サンプルへ飛ぶ |
| `o` | **対象セルの枠の表示 / 非表示**（既定は表示 ON。拡大率と表示位置は維持されます） |
| `n` / `Esc` | メモ欄に入る / 抜ける |
| `0` `+` `-` | ズームのリセット / 拡大 / 縮小 |

「判定を入力したら自動で次へ」を有効にしておくと、`1`–`4` を押すだけで流し込めます。
確信度やメモを毎回入れたい場合はオフにしてください。

**保存と書き出し**

- 入力はブラウザの localStorage に自動保存されます。ページを閉じても、
  同じブラウザで開き直せば続きから再開できます。
- **「CSV を保存」**で `interpretation_sheet_filled_<日時>.csv` がダウンロードされます。
  列構成は `interpretation_sheet.csv` と同一（`dist` などの元の列もそのまま引き継ぎます）なので、
  §6 の集計にそのまま使えます。§6 で `interpretation_sheet.csv` と書かれている箇所は、
  このダウンロードしたファイルに読み替えてください。
- **「CSV を読み込む」**で、書き出した CSV を読み戻せます（`blind_id` で照合し、
  `verdict` / `confidence` / `notes` を上書き）。別のマシンで続きをやる場合や、
  localStorage が消えた場合の復旧に使います。**作業の区切りごとに CSV を保存しておいてください。**

**盲検について**：ツールは `blind_id` と画像しか表示せず、`sample_key.csv` を一切読みません。
遷移タイプ・座標は画面にも書き出す CSV にも出ません。

**Chrome での動作確認**（初回に 1 分で済みます）

1. Chrome で `interpretation_tool.html` を開く。アドレスバーが `file:///…/interpretation_tool.html`
   になっていることを確認する。
2. 左上に `B001` と `1 / 129`、左側に 2×2 の画像が表示される。
   画像が出ない場合は、HTML を `blind/` と同じディレクトリから動かしていないか確認する。
3. ホイールを回して拡大、ドラッグで移動、ダブルクリックで元に戻ることを確認する。
   各パネルの中央付近にマゼンタの照準と細い枠が出ていることを確認する。
   `o` を押すと枠が消え、もう一度押すと戻る。拡大率と位置は変わらない。
4. `1` を押す → 「ササが実際に消えた」が青くなり、進捗が `1 / 129` に増える。
   もう一度 `1` を押すと取り消される。
5. 「CSV を保存」を押し、ダウンロードされた CSV の 1 行目が
   `blind_id,blind_image,dist,m_per_px_horiz,m2_per_px,align_shift_px,quality_ok,verdict,confidence,notes`
   になっていることを確認する。
6. Chrome を一度閉じて開き直し、手順 4 の入力が残っていることを確認する（localStorage の確認）。
   シークレットウィンドウでは保存されないので、通常のウィンドウで開いてください。

**再生成**：`python3 make_interpretation_tool.py`
（`interpretation_sheet.csv` を読み、サンプル一覧を JSON として HTML に埋め込み直します。
書き込むのは `interpretation_tool.html` だけです。`interpretation_sheet.csv` や `sample_key.csv`、
`blind/` には触れないので、判読中に実行しても入力内容は消えません。
枠つき画像のパスは `blind/` を `blind_overlay/` に置き換えて求めているだけなので、
`blind_overlay/` が無い場合は自動的に枠なし表示にフォールバックします。）

| 層 | 遷移 | n | 母集団（セル = m²） | 標本比 | 中央距離 |
|---|---|---:|---:|---:|---:|
| `loss_to_dwarfpine` | ササ → ハイマツ | 37 | 1,156 | 46.8 % | 609 m |
| `loss_to_otherveg` | ササ → その他植生 | 30 | 932 | 38.0 % | 488 m |
| `loss_to_rowan` | ササ → ナナカマド | 5 | 159 | | 640 m |
| `loss_to_maple` | ササ → カエデ | 3 | 85 | | 640 m |
| `loss_to_alder` | ササ → ハンノキ | 4 | 133 | | 770 m |
| （落葉低木 小計） | | **12** | **377** | **15.2 %** | |
| **減少 計** | | **79** | **2,465** | 100 % | |
| `control_stable_sasa` | ササ → ササ | 20 | 6,079 | 対照 | 604 m |

  見えるものが多ければ、それは分類器の不安定性の直接の証拠になります。

- 抽出は乱数シード `20260830` で再現可能です。

## 5. 既知の限界（結果を書くときに必ず踏まえること）

1. **樹冠の下は見えない。** 写真判読で言えるのは「木本の樹冠が旧ササ面を覆った」までで、
   その下でササが生きているかどうかは分からない。原稿では
   「減少画素は木本の樹冠が旧ササ面を覆った場所であり、これはササの林床残存と整合的で、
   ササの枯死とは整合しない」という形にとどめ、ササの耐陰性に関する文献を添えること。
   これより強い主張には現地データが要る。
2. **斜め写真なので鉛直方向のスケールは圧縮されており、未知。** スケールバーはすべて
   「水平方向」の値。切り出し画像から面積を測ってはいけない。
3. **幾何補正の誤差。**
   - 2012↔2021 の残差位置ずれ: 中央値 1.0 px、129 件中 124 件が 2 px 以下、最大 25.5 px。
     大きいものは画面下部の近景（視差が最大になる領域）に集中する。`align_shift_px` で選別可。
   - カメラモデルは `ortho/data/gcp.csv` の 482 GCP から再フィットしたもの
     （元の変換テーブル `data/georectified.csv` がリポジトリに無いため）。
     GCP 再投影誤差は RMSE 6.3 px / 中央値 2.3 px。
   - 1 m セルの投影位置には 10〜20 px 程度の系統的でない誤差が残る。ササのような希少で
     小さいクラスでは、投影点そのものより **±20 px の窓**で一致を見るべき。切り出し幅は
     121〜501 px なので判読には支障ないが、「中心 1 画素が対象セル」と厳密には言えない。
   - したがって `blind_overlay/` に描いた**対象セルの枠も 1〜2 セル分ずれうる**。
     枠は「この辺り」を示すものであり、枠の内外で 1 m の境界が厳密に決まるとは考えないこと
     （§3.1 の「対象セルの枠と照準」を参照）。
4. **年次間の撮影条件差。** 2021 年は絞りが f/11→f/13 になり約 10 % 暗い。注釈付き図では
   全体一律のゲインで補正し `[exp-matched]` と表示しているが、`crops_native/` は無補正。
   物候差は緑色度（GCC）でフレームを対応付けて抑えてある（2012-09-17 ↔ 2021-09-07、
   2012-10-06 ↔ 2021-10-02）が、太陽位置が違うため局所の影の出方は一致しない。
   また 2021 年の緑葉期フレームは実測でやや**甘い（低シャープネス）**ので、
   テクスチャの年次比較は下方バイアスを持つ。
5. **重ねてあるラベルは論文の地図と同一だが、最下段の独立分類は別のモデル実行結果。**
   論文の数値は 5×5 パッチモデル（`ortho/data/vege_*_5x5.tiff`）由来、
   最下段は 1×1 モデル（`results/*_masked.npy`）由来で、両者はササの扱いで大きく食い違う。
   この食い違い自体が「ササ／ハイマツ境界での分類不安定性」の証拠であり、
   切り出し画像の欠陥ではない。詳細は `feasibility_prev_session.md` §6。
6. **遠景ほど弱い。** 本パッケージでは全サンプルを `m_per_px_horiz < 0.25` に制限したので
   前セッション版のような遠景の対照は含まれていないが、それでも中央値 0.17 m/px であり、
   ハイマツの個体クッション（径 1〜3 m）が 6〜20 px に相当する程度。個々のシュートは見えない。
7. **盲検は不完全。** 遷移タイプは伏せてあるが、判読者は仮説を知っている。
   `notes` に判断根拠を残し、後から追跡できるようにしておくこと。

## 6. 判読後にすること

1. `interpretation_sheet.csv` を保存し、`sample_key.csv` と `blind_id` で結合する。
2. 層別に `verdict` を集計する。特に見るべきは、
   - `loss_to_dwarfpine` で `canopy_overgrowth` の割合 …「木本の被覆で見えなくなった」という
     原稿の主張を支持する割合。
   - `loss_to_dwarfpine` + `loss_to_otherveg` で `boundary_jitter` の割合 …
     これが高ければ、減少面積は生態学的変化ではなく分類の不確実性として報告すべき。
   - `control_stable_sasa` / `control_stable_dwarfpine` で `boundary_jitter` 以外が出る率 …
     判読自体の偽陽性率の推定値。
   - `gain_dwarfpine_to_sasa` の内訳 … 分類器の対称的な不安定性の直接の指標。
3. 対照層での誤判定率を使って、減少層の割合を補正して報告する。
4. 結論が「大半が `boundary_jitter`」であれば、誠実な改訂は
   「減少面積は分類の不確実性を反映するため、拡大面積（4,095 m²）を主指標とする」
   という形になる。現在の原稿の「木本の侵入と成長によるもの」という無根拠な断定は
   判読結果に置き換えること。

## 7. 再生成

```sh
python3 -m venv --system-site-packages venv     # システム python に osgeo/GDAL が入っている
venv/bin/pip install numpy pillow matplotlib scipy
venv/bin/python sample_loss_crops.py --outdir . --seed 20260830 --n-loss 80 --n-control 20
python3 make_interpretation_sheet.py --seed 20260830      # blind_id を割り当て直す（下の注意）
venv/bin/python make_blind_overlays.py                    # blind_overlay/ を作る
python3 make_interpretation_tool.py                       # HTML ツールを作り直す
```

所要 1〜2 分（`_cache/` があれば）。`_cache/` を消せば完全にゼロから再計算します。
スクリプトはリポジトリに対して読み取り専用で、書き込むのは `--outdir` のみです。

主なオプション: `--n-loss`（減少サンプル総数、遷移先へ比例配分）、`--n-control`（対照層あたり）、
`--max-m-per-px`（地上分解能の上限、既定 0.25。`0` で無効化）、`--no-exposure-match`。

`make_blind_overlays.py` は `sample_key.csv` の `u`, `v`, `x`, `y` と `_cache/cam.npz` の
カメラモデルだけを読み、`blind_overlay/` と `blind_overlay_footprints.csv` を書きます。
`blind/`・`interpretation_sheet.csv`・`sample_key.csv` は変更しません。

**注意:** `make_interpretation_sheet.py` を再実行すると `blind_id` の割り当てが変わります。
判読を始めたあとは実行しないでください（`make_blind_overlays.py` と
`make_interpretation_tool.py` は再実行しても `blind_id` を変えません）。
